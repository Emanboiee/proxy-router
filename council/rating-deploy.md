FINDINGS:

1. P1 — `provider_lifecycle.py:313-320` → `router.py:1241`: CONNECT-rejection record is a full-file replace, not a merge; it clobbers all other egress fields.
   `recover_routed` builds a fresh `{"ok": False, "checked_at":…, "socks_connect_ok": False, "error":…}` and hands it to `write_egress`, which overwrites the whole `state/egress/<provider>/<synthetic>.json`. That silently deletes `fails`, `blocked`/`block_reason`/`blocked_until`, `exhausted`/`quota_until`, `latency_ms`, `dns_ok`, `tls_fails`, `last_ok_at` — all bookkeeping `record_egress()` normally maintains. Consequence for the #219 gate: `provider_quota_exhausted()` (router.py:1357) reads `exit_unusable = quota_active OR quota_unknown`. A just-written failure record is fresh and has no `exhausted` key, so both are False → an exit that was quota-blocked or reputation-blocked is reported eligible again. It also bypasses the fail-streak/debounce that the normal `record_egress(ok=False)` path applies. No test covers this. Suggested fix: load `read_egress(name, profile)` (or pass a merge-aware writer) and update in place — set `ok=False`, `checked_at=now`, `socks_connect_ok=False`, `socks_connect_code`/`error`, leave quota/block/fails fields intact — and add a regression test that a CONNECT rejection preserves a pre-existing `exhausted`/`blocked` marker.

2. P2 — `provider_lifecycle.py:313`, `router.py:2256-2281`: CONNECT rejection short-circuits `check_egress_live` to "dead", which is the keepalive auto-rotation trigger.
   Previously "dead" required a failed HTTP probe through the tunnel; now a SOCKS REP=4/5 on the upstream returns `("dead", record)` before the HTTP probe. The raw record has no `fails` counter, so the only debounce is the shell-level `DEAD_STRIKES=2` in examples/keepalive.sh (2 consecutive dead checks + rotation budget). That does prevent a single transient blip from rotating (acceptance #7 is mostly met), but a sustained WARP-side rejection now rotates this proxy provider's exit pool — which may not repair a transport-level WARP failure. Suggested fix: document that a CONNECT rejection is a "dead tunnel" signal and confirm with a keepalive/egress_check end-to-end test that a rejection yields `dead: <provider>` within the bounded interval and rotates at most once per strike budget; consider reporting "degraded" (not "dead") for REP=4/5 to keep rotation strictly for HTTP-probe death.
