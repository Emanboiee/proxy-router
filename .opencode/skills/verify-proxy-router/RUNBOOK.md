# Rebuild a proxy-router instance from a fresh clone

A clone alone will not run. Several required files are gitignored runtime state
and two source files (`codex_gateway.mjs`, `network_guard.py`) are operator-local
and not in the repo. This runbook records the sequence. Do the steps in order;
each ends in a check. Stop on any failed check.

## 1. Clone and test

```bash
git clone --depth 1 --branch main <REPO_URL> proxy-router
cd proxy-router
python3 -m pytest tests/ -q
```

Check: suite passes.

## 2. Restore gitignored runtime state

`.gitignore` excludes `router.json`, `sing-box.json`, `state/`, `logs/`,
`providers/`, `presets/`, and `configs/`. Copy these from the previous install
or regenerate them with `router.py setup --preset <name>` and
`router.py init`. At minimum:

- `router.json` — routes, providers, fallback chains, port.
- `sing-box.json` — generated by `router.py start`; may be copied to preserve egress.
- `providers/<name>/*.conf` — WireGuard profiles (bring-your-own).
- `state/` — active-profile and cooldown markers.
- `logs/` — created automatically.

Check:

```bash
python3 router.py providers check --json   # expect the intended providers valid
```

## 3. Restore operator-local source files

If the install used `codex_gateway.mjs` or `network_guard.py`, restore them from
the operator's own backup; they are not tracked. Then compile-check:

```bash
python3 -m py_compile router.py network_guard.py
```

## 4. Verify the fallback chain

`router.json` should declare each primary's fallback, for example:

```json
"cloudflare": {
  "socks5": { "host": "127.0.0.1", "port": 2181 },
  "fallback_providers": ["proton"]
}
```

Check: `python3 router.py failover cloudflare status --json` shows the chain.

## 5. Repoint launchd jobs (macOS)

Back up each plist first. Replace the old checkout path in the path-bearing
plists (`keepalive`, `model-relay`, `codex-gateway`). The dashboard resolves its
root from `PROXY_ROUTER_ROOT` and defaults to `~/proxy-router`, so its plist
needs an `EnvironmentVariables` dict:

```
PROXY_ROUTER_ROOT=<absolute path to this checkout>
PROXY_ROUTER_PYTHON=<absolute path to pinned python3>
```

Use a pinned interpreter whose default is not a stale system python. Validate
and reload:

```bash
plutil -lint /path/to/plist
launchctl bootout "gui/$(id -u)/com.proxy-router.<job>"
launchctl bootstrap "gui/$(id -u)" "/path/to/plist"
```

## 6. Hand off a running engine

Editing plists does not move a live listener. The old engine holds the port and
the new controller treats it as foreign. Stop the old engine, confirm the port
frees, clear the stale pid, then start from the new root:

```bash
cd /old/checkout && python3 router.py stop
# confirm: lsof -nP -iTCP:2080 -sTCP:LISTEN returns empty
rm -f /new/checkout/sing-box.pid
cd /new/checkout && python3 router.py start
```

On a fresh boot with no running engine, skip the stop/start and just bootstrap
the jobs.

## 7. Verify

```bash
PROXY_ROUTER_ROOT=/new/checkout PROXY_ROUTER_PYTHON=/path/to/python3 \
  ./.opencode/skills/verify-proxy-router/verify.sh
```

Expect zero failures.

## Gotchas

- WARP can report Connected while its SOCKS listener is briefly down; egress
  check catches this. A soft `warp-cli disconnect` leaves the port up, so it
  proves manual failover but not the automatic dead-relay trigger.
- The dashboard is an orphanable menu-bar app. Quit a stale instance before
  bootstrapping the launchd job, or the new one cannot take the tray item.
- The privileged helper runs from `/Library/PrivilegedHelperTools/...`, not the
  checkout. A repoint does not update it.
- A shallow clone needs `git fetch --unshallow` before building a PR from it.
- Never kill by process name. Stop via `router.py stop` or launchd only.
