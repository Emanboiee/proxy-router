# proxy-router audit — 6 September 2026

## Assessment

The current working tree is not ready for a new release. The strongest immediate evidence is a broken Unix installation transaction, a release smoke test that skips before the archive exists, incorrect routing-list intersections, and an ambiguous reload result that lets callers mistake recovery for application of a requested change.

The project has substantial defensive work worth preserving: a separate privileged helper, exact sudoers commands, root-owned and digest-verified helper binaries, constrained generated-config validation, process identity checks, private atomic config replacement, bounded recovery attempts, and a pytest safety layer. Those strengths do not establish correctness at the boundaries between installer, controller, workers, and UI. Most actionable defects in this audit occur at those boundaries.

Implement the release and correctness repairs before decomposing the monolith. The companion [implementation plan](plans/2026-09-06-proxy-router-improvements.md) gives an ordered PR sequence, validation requirements, dependencies, and effort estimates.

## Detailed findings

### F01 — Unix installer does not publish the staged application

**Evidence:** [install.sh](/Users/kyson/proxy-router/install.sh:109).

1. The stage contains runtime files and `router.example.json`, but no `router.json`. Its smoke command requires `status --json` to exit zero. The controller correctly exits nonzero for missing configuration or a stopped engine. A clean install therefore aborts before publishing anything.
2. With `PROXY_ROUTER_SKIP_SMOKE=1`, the script creates `STAGE/final-name` as a symlink and moves that symlink into `PREFIX/releases/RELEASE_TAG`. It never moves the actual staged directory there. In the reproduction, `releases/dev` was a symlink to `releases/dev`; `current/router.py` did not exist even though the script exited zero.
3. `install_runtime` copies only three example files and omits the guides/rulesets trees and other advertised integrations. Fixing the directory promotion alone will not produce a complete installation.
4. The intended immutable-release layout needs a separate state root. [router.py](/Users/kyson/proxy-router/router.py:43) defaults ROOT to the resolved script directory. Launching a real release through `current/router.py` would therefore look inside the release for configuration, while the installer writes live configuration at the prefix root.
5. Rollback selects a lexically sorted remaining directory instead of a recorded previous successful target. `ln -sfn` is also not an adequate specification of an atomic transactional commit.

**Impact:** first installation cannot deliver a usable CLI; the bypass can falsely report success; a partial repair leaves state and resources misplaced.

**Repair:** promote the staged directory itself; separate code/resources from mutable state; install a launcher that explicitly selects the state root; validate an offline fixture before promotion; record previous/current versions; replace a temporary current symlink atomically on the same filesystem. Do not use a smoke bypass as the fix.

**Acceptance:** install, repeat-install, upgrade, forced interruption, and rollback all work in isolated prefixes; the installed CLI can print help and validate a fixture; all resources exist; user config and profiles survive unchanged.

### F02 — The release gate does not exercise the artifact it publishes

**Evidence:** [.github/workflows/release.yml](/Users/kyson/proxy-router/.github/workflows/release.yml:1).

The Unix clean-install smoke step precedes Archive. It tries extracting the not-yet-created tarball, ignores the extraction error, and exits successfully when `/tmp/proxy-router` is absent. On a clean runner the installer is never exercised. If that directory happens to exist, the test can use stale contents. The smoke also passes `PROXY_ROUTER_SKIP_SMOKE=1` as a positional argument rather than an environment assignment and tests `status` as if a disconnected fresh install should exit zero.

The checksum lookup returns an empty digest for non-Darwin assets and explicitly skips verification. A workflow-dispatch version can also disagree with the checked-in release manifest. The source bundle omits `pyproject.toml` and `requirements-dev.txt` while carrying tests and workflows that depend on them. Native CLI smoke is absent for Windows. The Intel macOS build comments promise download-only assembly but the validation step executes the binary; cross-architecture execution must be deliberately supported or separated from metadata inspection.

**Impact:** release publication can succeed without detecting F01 or Windows CLI failure; Linux/Windows downloads have weaker integrity guarantees than the root-helper distribution.

**Repair:** archive first, extract into a unique directory, install that exact extraction, reject missing manifest digests/version mismatches for every platform, smoke the native CLI, and include test metadata in source bundles. Give write permission only to publication jobs.

**Acceptance:** deliberately missing archives, broken installers, absent resources, wrong engine versions/digests, and missing source-test metadata each fail the release gate.

### F03 — Windows is advertised but cannot import the controller

**Evidence:** [router.py](/Users/kyson/proxy-router/router.py:24), [install.ps1](/Users/kyson/proxy-router/install.ps1:45), [test workflow](/Users/kyson/proxy-router/.github/workflows/test.yml:1).

`router.py` unconditionally imports `pwd`, which is Unix-only; Python documents that availability in its [pwd reference](https://docs.python.org/3/library/pwd.html). Calls to `os.geteuid()` also appear in shared write/lock paths. Mocking `sys.platform` on macOS does not reproduce the absence of Unix modules/APIs on Windows.

The PowerShell installer enumerates `presets` unconditionally with `ErrorActionPreference=Stop`, although the release assembly does not include that user-local directory. It adds the engine bin directory to PATH without creating a proxy-router command launcher there. These are separate installation and usability gaps.

**Impact:** even `--help` can fail on Windows; installer failure can leave partially copied files.

**Repair:** either explicitly narrow the supported-platform contract or implement portable identity/locking/launcher behavior and a real native Windows test job. Guard optional resource directories and make Windows installation transactional as well.

**Acceptance:** on an actual Windows runner, unpack → install → help → init/check fixture → status JSON works without Unix APIs. No live tunnel is required for that test.

### F04 — A rejected configuration can be recorded as active

**Evidence:** [engine_reload](/Users/kyson/proxy-router/router.py:3597), [restore_last_good](/Users/kyson/proxy-router/router.py:2647), [rotate](/Users/kyson/proxy-router/router.py:3712).

When candidate validation fails, `engine_reload()` returns `restore_last_good()` directly. Recovery returns zero when the previous configuration is restored. The reproduction forced validation failure and successful recovery; `engine_reload()` returned zero. `rotate()` interprets zero as candidate success, writes the chosen active profile and rotation record, and can then probe the restored old profile while attributing its health to the candidate.

There is a second transaction-order problem on rotation rollback: the previous profile marker and rotation record are written before the rollback reload succeeds. State can therefore disagree with the engine in both directions.

**Impact:** misleading UI/status, incorrect cooldown/health attribution, and incorrect subsequent failover decisions.

**Repair:** return a structured outcome containing `requested_applied`, `service_restored`, `applied_generation`, and error details. Preserve a nonzero CLI result when the requested change failed, even if recovery restored service. Commit profile/fallback markers only after evidence that the corresponding generation is active.

**Acceptance:** candidate rejection + successful recovery keeps old markers and returns a failed-change result; failed rollback never claims a restored profile; health records reference the generation actually probed.

### F05 — VPN-list filtering loses the intersection with a broader provider route

**Evidence:** [build_singbox_config](/Users/kyson/proxy-router/router.py:2307), [_route_capture_cidrs](/Users/kyson/proxy-router/router.py:2213), [watcher provider lookup](/Users/kyson/proxy-router/route_watcher.py:337).

Given a provider route for `example.com` and `vpn_domains=["api.example.com"]`, the compiler only retains a route domain when it is equal to or below the VPN-list domain. It drops `example.com` rather than emitting the narrower intersection `api.example.com`. The reproduction generated no provider or provider-DNS rule, leaving the default direct route. The watcher uses a different overlap calculation and can disagree about what is tunneled.

**Repair:** normalize domain suffixes and calculate their intersection once: if one suffix contains the other, emit the narrower suffix. Reuse the result for data-plane rules, DNS rules, capture planning, watcher inference, and status explanations. Reject empty domains and normalize casing/trailing dots consistently.

**Acceptance:** parent/child in both directions, equal domains, siblings, mixed case, trailing dots, direct-list overrides, and unknown providers have deterministic golden outputs. The generated rules must not broaden the requested VPN-list scope.

### F06 — IP snapshot capture is not a complete domain-routing implementation

**Evidence:** [_route_capture_cidrs](/Users/kyson/proxy-router/router.py:2213), [TUN generation](/Users/kyson/proxy-router/router.py:2441).

Explicit `vpn.capture="routes"` installs IP routes resolved from configured route hostnames at build time. Resolving `example.com` does not enumerate all IPs used by `*.example.com`; DNS/CDN answers also change. Traffic to addresses outside that snapshot never reaches sing-box, so its correct domain rules cannot help.

The stronger mismatch is safe-list mode: its user-facing meaning is that everything outside the direct list uses the default provider, but selective capture still only gathers configured-route IPs. Traffic outside that capture can bypass the engine. Severity is P1 if this is presented as a privacy guarantee; otherwise it is a P2 contract/design issue for a selective connectivity tool.

DNS is deliberately sent on the direct path. Missing usable providers can also cause their rules to be omitted in default/VPN-list modes. These behaviors are not automatically defects—the README describes direct fallback—but the product must not imply a kill switch or complete DNS privacy.

**Repair:** specify a mode compatibility table. Reject combinations whose policy cannot be enforced; consider full capture for safe-list mode, or label it as applying only to proxy/captured traffic. For selective mode, choose between explicitly managed IP rules, a controlled DNS-to-route update mechanism, or broader capture with deliberate bypass rules. Explain QUIC, encrypted hostname metadata, shared CDN IPs, and IPv6 limits.

**Acceptance:** isolated integration tests vary DNS answers and subdomain destinations, exercise IPv4/IPv6 and unmatched safe-list traffic, and verify the actual path—not merely generated JSON.

### F07 — The watcher can perform an automatic TUN rotation as if it were manual

**Evidence:** [rotate_provider](/Users/kyson/proxy-router/route_watcher.py:369), [worker](/Users/kyson/proxy-router/route_watcher.py:419), [rotate safeguard](/Users/kyson/proxy-router/router.py:3712).

The watcher invokes `rotate PROVIDER --reason timeout` without `--automatic`. The controller only rejects automatic TUN rotations when that flag is present. Keepalive correctly supplies it; the watcher does not. The watcher also uses its own transport classifier and fallback provider guesses (`proton`) instead of the controller's effective routing/health decision.

**Impact:** background observation can interrupt the shared TUN despite the documented automatic-maintenance safeguard, or select the wrong provider for an ambiguous/direct flow.

**Repair:** send an explicit operation origin for every supervisor action, validate manual-off and positively proven proxy mode under the controller lock, and use one effective-route/health API. Ambiguous provider identity should generate a diagnostic, not a guessed rotation.

**Acceptance:** watcher errors in TUN, unknown mode, manual-off, direct safe-list domains, and active fallbacks do not reload an unrelated/shared engine. Test a mode change between observation and command execution.

### F08 — Atomic file replacement does not prevent lost configuration updates

**Evidence:** [main dispatch](/Users/kyson/proxy-router/router.py:6050), [save_config](/Users/kyson/proxy-router/router.py:3870), [_routing_mutate](/Users/kyson/proxy-router/router.py:4020), [setup writers](/Users/kyson/proxy-router/setup_tui.py:503).

The main config load happens before most lifecycle locks. Route add/remove take a lock around a mutation of the already-loaded `_routes`, then overwrite the routes section in the latest file. Two processes that loaded the same initial state can serialize their writes and still lose the first update. A sequential stale-snapshot reproduction demonstrated this loss. Routing-list commands and multiple setup writers do not share that lock at all.

**Repair:** lock the complete read → validate → mutate → persist sequence for each writer. Reload inside the critical section; use a generation/hash check for long operations that release the lock while probing. Separate a short configuration transaction lock from lifecycle work, document lock ordering, and never hold it over network settling.

**Acceptance:** concurrent add/add, add/remove, routing-list/preset, profile import/config, and reload/config cases either preserve both changes or report a conflict. Atomic-write durability should also be tested with injected failures; add fsync where durable state is required.

### F09 — The SSRF check is separate from the connection it attempts to protect

**Evidence:** [monitor target resolution](/Users/kyson/proxy-router/monitor.py:122), [monitor request](/Users/kyson/proxy-router/monitor.py:250), [curl probe](/Users/kyson/proxy-router/router.py:1331), [urllib probe](/Users/kyson/proxy-router/router.py:1392).

Monitor resolves a hostname for validation and then passes the original URL to urllib, which can resolve it again and follows redirects through its default opener. Redirect targets are not revalidated. Resolution failures produce an empty list, which the validator accepts; only the first eight returned addresses are examined. Curl probes validate local resolver answers but ask an HTTP proxy to connect to the original hostname, so the proxy may use a different answer. This does not establish the claimed DNS-rebinding protection.

Python's [urllib documentation](https://docs.python.org/3/library/urllib.request.html) describes the default redirect and proxy handlers. This is a source-confirmed enforcement gap, not a live exploit test; impact requires an attacker-influenced target/response/DNS path. The monitor runs with user privileges, not automatically as root.

**Repair:** validate the destination at the component that performs the connection; retain HTTP Host and TLS SNI/certificate verification while binding to approved addresses. Disable redirects by default for health probes or revalidate every hop with a small limit. Do not accept unresolved hosts as proof of safety. For proxied traffic, use an explicit engine-side private-address policy or a transport that can prove its dial target.

**Acceptance:** public-to-private redirects, answer changes, resolver failure, mixed public/private answers, IPv6/metadata destinations, proxy-side answer differences, and bypass behavior all have hermetic tests. No request reaches the forbidden test destination.

### F10 — Privileged reload readiness is weaker than unprivileged readiness

**Evidence:** [_wait_started](/Users/kyson/proxy-router/privileged_helper.py:826), [reload_engine](/Users/kyson/proxy-router/privileged_helper.py:908), [controller helper branch](/Users/kyson/proxy-router/router.py:3630).

The helper waiter returns true on the first successful `process_matches` call. The reproduction needed one positive identity check and no listener, route, settle, or applied-config check. An existing process immediately after SIGHUP satisfies that predicate even if its reload is unfinished or subsequently fails. The controller's helper reload branch then writes last-good and active markers immediately on helper success.

**Impact:** the privileged path can declare and snapshot success with weaker evidence than the regular controller path. Config syntax validation is valuable but does not prove runtime application.

**Repair:** split identity/liveness from readiness, preserve the old root config until the candidate is confirmed, and use a bounded generation-aware readiness protocol with rollback. Keep the helper's privileged capability set narrow; user-level egress checks can remain outside root when the protocol supports them.

**Acceptance:** the process survives while reload fails, delayed fatal errors, listener bind failure, old-generation service, and candidate startup failure all produce accurate results and preserve the recoverable configuration.

### F11 — Configuration validation is fragmented and incomplete

**Evidence:** [load_config](/Users/kyson/proxy-router/router.py:332), [setup check](/Users/kyson/proxy-router/setup_tui.py:762), [watcher config reads](/Users/kyson/proxy-router/route_watcher.py:132), [helper rule validator](/Users/kyson/proxy-router/privileged_helper.py:1271).

Reproduced cases:

- Cycles expressed with plural-key strings or legacy-key lists load successfully. The cycle traversal only recognizes plural-key lists and legacy-key strings, although loading accepts all four encodings.
- A route containing only `provider` passes load and generates an outbound-only rule. The helper rejects that rule because it requires a matcher. The unprivileged compiler must also reject this malformed intent before engine validation.
- A top-level JSON array causes `AttributeError` in `setup.check`, `watcher.critical_domains`, and `watcher.router_port` instead of a structured configuration error.

Further divergence: the controller accepts ports below 1024 while the privileged envelope requires 1024–65535. `setup --check` checks profile availability but does not validate the full routing schema it is advertised to check. Several monitor/watcher readers silently substitute defaults, which can probe a different endpoint/port than intended.

**Repair:** normalize aliases first, validate a single typed schema, and share its error model. Run cycle detection over the normalized graph with visited/visiting sets. Validate route matchers, domains/CIDRs, numeric bounds, finite values, and mode-specific helper constraints before writing. Distinguish an absent optional setting from malformed configuration.

**Acceptance:** every reader agrees on valid/invalid fixtures; all supported fallback encodings produce the same normalized graph; malformed input never crashes a status/check command or silently widens routing.

### F12 — Disconnect suppresses a consequential stale-service failure

**Evidence:** [system_proxy_off](/Users/kyson/proxy-router/router.py:5172), [stop dispatch](/Users/kyson/proxy-router/router.py:6012).

The secondary-service sweep catches a failure clearing an owned proxy and continues, returning zero. A mocked Wi-Fi success plus Ethernet failure reproduced exit zero. The Stop caller may then terminate the engine while the other service still points to it. `_proxy_points_at_us` uses `_port`; emergency stop bypasses config loading, so non-default-port ownership needs separate treatment. Checking either HTTP or HTTPS as owned and then disabling both also does not preserve a foreign setting in the other protocol slot.

**Repair:** track installed proxy ownership per service/protocol/port, return an aggregate partial-failure result, and preserve service until owned endpoints are cleared or the operator explicitly requests a forced shutdown. Snapshot prior settings at connect time if restoration is part of the contract; restore only state still owned by this installation.

**Acceptance:** inactive-service failure, non-default ports, network handoff, mixed foreign/owned protocol settings, and corrupt config all produce honest state without stranding traffic or altering an unrelated proxy.

### F13 — Tray timeout can kill a legitimate multi-step rotation

**Evidence:** [tray command runner](/Users/kyson/proxy-router/proxy_tray.py:413), [probe settling](/Users/kyson/proxy-router/router.py:1507).

All tray commands have a 20-second subprocess timeout. Rotation can include engine reload, an 8-second probe, repeated probes during a default 20-second settling window, and rollback. The generated default configuration can set an even longer settle. The TUI already grants rotations a larger deadline. A tray timeout can therefore kill the controller after it has changed the engine/markers, leaving a failed UI action with partially completed work.

**Repair:** give operations explicit budgets and cancellation semantics. Separate a quick acknowledgement from long-operation progress, or use bounded operation-specific deadlines until a job protocol exists. On timeout, reconcile the operation ID/applied generation before permitting another mutation.

**Acceptance:** slow valid rotation, timed-out probe, rollback, disconnect during settling, and Quit during mutation all reach an explicit terminal result with matching engine/state/UI.

### F14 — Worker and resource-control gaps remain

**Evidence:** [monitor start/stop](/Users/kyson/proxy-router/monitor.py:537), [watcher start](/Users/kyson/proxy-router/route_watcher.py:633), [watcher log read](/Users/kyson/proxy-router/route_watcher.py:383), [probe body capture](/Users/kyson/proxy-router/router.py:1331).

- Monitor/watcher start use check-then-spawn without a shared cross-process worker lock. Concurrent starts can create multiple workers and overwrite the PID record.
- Monitor stop removes state immediately after attempting SIGTERM; it does not confirm exit. A worker can recreate the enabled marker at startup. Watcher has better stop/ownership handling but does not eliminate the start race.
- Watcher reads all appended log lines at once and tracks an offset without inode identity; replacement or rapid truncation/regrowth can skip data. Host-keyed caches retain idle keys.
- Generated sing-box logging is hardcoded to `warn`, while normal connection observations parsed by the watcher require corresponding log events. The source mentions a `log-level` CLI command that is not implemented. The watcher can therefore appear running while lacking the observations needed for its normal probes.
- Curl captures the entire response before slicing the body to 4096 characters. A time limit is not a byte limit. Monitor counts all existing sample lines before every append and its per-read timeout is not a total sample deadline.
- The separate IPv6 CONNECT tool uses unbounded per-connection threads and blocking pumps. It is a developer utility, not a hardened general proxy.

**Repair:** shared worker ownership/start/stop primitives; byte-bounded incremental log reads with inode tracking; bounded/expiring caches; explicit observation capability; streaming bounded probe transport; total operation deadlines and resource budgets. Keep the IPv6 utility experimental or add connection/idle/header limits and lifecycle tests.

**Acceptance:** concurrent starts yield one worker, stop confirms termination, log rotation does not lose/duplicate events unexpectedly, large responses/log bursts remain memory-bounded, and no worker silently claims useful health without input data.

### F15 — Current test and documentation contracts miss operational boundaries

**Evidence:** [pytest configuration](/Users/kyson/proxy-router/pyproject.toml:1), [CI contract test](/Users/kyson/proxy-router/tests/test_ci_contract.py:32), [release tests](/Users/kyson/proxy-router/tests/test_release_bundle.py:1), [test safety classifier](/Users/kyson/proxy-router/tests/safety.py:58).

The CI contract asserts that the workflow has exactly one macOS-only job, so adding needed platform coverage requires changing that contract intentionally. Release tests mostly assert file names and strings, which do not catch the broken install transaction or skipped smoke step. README Development still recommends unittest discovery, bypassing pytest fixtures/plugins and their safety protections; its layout also describes tests as dependency-free despite the pytest imports.

The safety layer is useful but not a general OS sandbox: its command classifier recognizes particular forbidden patterns and otherwise permits commands, and in-process monkeypatches do not automatically constrain arbitrary child scripts. Treat it as regression protection, strengthen it, and execute integration tests in disposable environments.

Untracked config backups are not covered by the current backup ignore patterns. They were not inspected for secret content. A backup name alone is not evidence of exposed credentials, but accidental staging is avoidable.

**Repair:** establish a reproducible test environment, local test package identity, behavior-level artifact tests, native-platform smoke, deterministic seeded tests, and a canonical developer command. Add secret scanning/backup ignore policy and regression-focused coverage rather than an arbitrary global percentage target.

### F16 — Architecture makes cross-component invariants expensive to maintain

AST inspection found 6,309 logical lines in router.py and 218 function definitions including nested functions. `main()` spans 509 lines; the config builder spans 278. Setup contains 2,934 logical lines. Size alone is not a correctness defect: the concrete problem is mutable module state plus duplicated config reading, route inference, PID interpretation, command execution, and health classification.

The existing [refactor plan](/Users/kyson/proxy-router/docs/REFACTOR_PLAN.md) is directionally useful. Refine it around explicit value objects and transaction outcomes rather than merely moving functions. The root helper must retain independent validation of untrusted requests; do not collapse that security boundary into an unprivileged convenience layer. Avoid naming a top-level package `platform`, which could shadow the standard library.
